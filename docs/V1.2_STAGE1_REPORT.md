# V1.2 第一阶段：正式战斗立绘接入

工程：`D:\项目\1`，Godot `4.7.2.stable.official.ed1daf0bf`。

修改前使用独立备份保护 V1.1：`backups/v11_before_v12_stage1/`。该目录没有 Git 仓库。修改前 smoke 和退出测试通过。所有测试使用 `.local_test/` 内独立 APPDATA，没有清空玩家长期 Mastery。

## 具体修改

- 玩家加载提供的 `assets/characters/word_mage.png`，精英第三场加载 `assets/enemies/marginalia.png`。这两个资源路径沿用原接口。
- 在 `actor_view.gd` 新增 PNG 专用 `texture_height` 与等比缩放上限，为待机摆动和攻击位移留出边距。两个角色设计高度均设为 435，1280×720 下画布高度约 291px；玩家可见人物因透明边距略小。
- `actor_art.gd` 提取复用的纹理绘制矩形；没有拉伸、镜像或修改原 PNG。
- 原有 `visual → pose → art` 节点关系保持：Idle、Attack、Hit、Death 继续作用于同一张纹理。
- 原有程序绘制回退仍保留；普通敌人与 Boss 的比例、资源路径与动画未改。
- smoke 的缺图回退测试改为显式加载不存在的测试路径，以便安装正式图片后仍能验证回退。
- 新增 `tests/artwork.gd`，用于导入、透明通道、等比尺寸、UI 遮挡及动画路径验证。

词库、Mastery、战斗数值、奖励和存档脚本均未修改。

## 素材验证

两张 PNG 都是 1086×1448，有效 alpha 模式为 BLEND（半透明）。每四像素采样：Word Mage 的透明样本 53160、可见样本 39986；Marginalia 的透明样本 49139、可见样本 46595。它们不是带不透明底色的矩形图片。

已使用 Godot 编辑器导入，生成正常 `.png.import` 配置与引擎纹理缓存。实际图形测试通过 Texture2D 资源加载。

## 实际测试

1. `Godot --headless --path . --editor --import`：两张 PNG 成功导入。
2. `powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run_smoke.ps1`：`PASS | words=120 | failures=0`，菜单退出测试正常结束。
3. 隔离测试存档下 `Godot --headless --path . --script res://tests/artwork.gd`：导入、透明、等比、遮挡和动画专项测试通过。
4. 隔离测试存档下 `Godot --path . --resolution 1280x720 --script res://tests/artwork.gd`：使用 NVIDIA RTX 4070 SUPER OpenGL 实际渲染，`ARTWORK RESULT: PASS | failures=0`，退出码 0。

最终图形模式实测：玩家画布约 290.7px，精英约 291.2px。专项测试从标题进入普通战，再通过精英入场切换至第三场，验证 PNG 加载、待机浮动、施法位移、反击完成、死亡渐隐与奖励页。立绘边界没有与魔法卡、四个选项或血条相交。

检查了 `.local_test/artwork/` 中普通战、精英战、玩家施法和精英反击的 1280×720 渲染截图。画面显示方向正确，没有发现 UI 遮挡。

## 人工检查重点

重新 F5 启动，留意两张立绘在不同窗口尺寸下的大小；检查蓝金/紫红发光边缘在深色背景上的自然程度；感受施法、受击闪亮及死亡淡出的节奏。图形脚本已执行实际动画，但没有进行人工完整游玩。本阶段没有修改或清理素材本身的光晕像素。
