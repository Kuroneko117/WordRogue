# V1.9 立绘尺寸修正

针对用户截图中纸页傀儡明显小于主角的问题修正。

## 原因与修改

- 敌方意图与说明占用了角色列，等比缩放受剩余高度约束，导致怪物被缩得很小。攻击预告与警示移动到下方战术栏，右側仅保留名称、类型、HP与蓄势和立绘。
- 主角展示目标435设计单位，普通480、幽灯430、边注510、档案官520。Boss目标610并单独加宽列；实际均受安全区域约束，不拉伸、不裁切。
- 两侧角色使用共同落脚基线，保留Idle浮动。施法原点随角色实际变换计算，保留三法术与原Attack/Hit/Death的pose结构。
- 只修改scripts/ui/battle_view.gd、scripts/ui/actor_view.gd、scripts/presentation_profiles.gd中的展示配置。战斗数值、词库、Mastery、存档与音频未修改。

修改前备份：backups/v19_before_actor_size_fix_20261011_182412/。

## 定向验证

Godot 4.7.2真实图形窗口，独立.local_test/v19_size_profile存档。脚本tests/v19_actor_sizes.gd。

通过：1280×720与1920×1080下八种怪物等比显示、怪物/主角比例、共同落脚基线、题卡/答案/HP/蓄势/战术栏不被遮挡；满蓄势与Boss二阶段标题；三法术动画与纸拳受击后恢复位置。

没有重复运行地图或战斗平衡模拟。结果与尺寸数据：.local_test/v19_size_fix/result.json；截图分别在1280x720和1920x1080子目录。截图为怪物展示测试夹具，其中HP来自原敌人定义，用于比较外观；正式冒险的短局HP配置未改。

本修正覆盖原V1.9报告中的角色展示尺寸与意图栏位置说明，其他交付内容不变。
