# WordRogue V1.9 UI设计规范

## 结构与信息

- 根节点铺满视口，用MarginContainer留边，HBox/VBox/Grid分配区域。1920×1080逻辑画布，1280×720时比例缩放。
- 统一使用ui_kit.gd的深蓝墨色、羊皮纸文字、暖金行动、青蓝玩家、紫红敌方。游戏页面由具体View生成，展示构建器不结算战斗。
- 主要安全边距64，页面间隔20–28；卡片内边距16–24。容器内不要使用固定位置排版。
- 标题48–86、区块32–38、正文/按钮26–30、补充22–25设计字号；小窗口正文约17–20px。中文使用系统雅黑/黑体回退。
- 横向自动换行Label必须得到实际可用宽度，不允许以最小1px宽度挤成长列。地图画布高度由容器可用空间决定，禁止尺寸与最小高度循环增长。
- 玩家、单词、敌人各占独立列；角色均匀缩放并留受击/待机移动空间。法术只作用于pose/art，不移动Container的布局边界。

## 交互

- 按钮正常/悬停/按下/禁用/键盘焦点都有反馈；焦点用青蓝边框。按钮最小高度72，作答100以上。
- 图标必须配文字或说明，地图区分可进入/已完成/已错过/未到达/当前位置。遗物滚动列表接收悬停tooltip。
- 显示真实法力与强化后的效果；不足禁用，并给出原因。满蓄势必须解释答对仍可受反击，不能让玩家误以为失去攻击。
- 新页面给合理初始焦点；Tab、方向键、Enter可操作。1–4与Q/W/E是快捷键，ESC由原暂停层处理。
- 选择后立即锁定，Reward要递归禁用嵌套按钮。保留原状态机、epoch取消与一次领取校验，视觉反馈不再调用数据结算。
- 事件交易显示生命价格与禁用理由；回忆答题和战斗题分区；报告统一“总答题=正确+错误”，去重词数另列。

## 外部参考的采用范围

- [官方GUI示例](https://github.com/godotengine/godot-demo-projects/tree/master/gui)：MIT；容器、canvas_items、运行时StyleBox覆盖、初始焦点。
- [shadcn UI kit](https://github.com/godot-collective/godot-shadcn-ui-kit)：MIT；已阅读skill/agent文件，采用共享token、锚点、稳定字段引用、不调用编辑器API。该仓库的静态demo镜像规则不适用于本工程。
- [GodotUIFramework](https://github.com/Liweimin0512/GodotUIFramework)：MIT；README的主题/过渡/组件职责思路。未安装插件，未验证第三方框架实际运行；docs/theme.md访问404。

只吸收规范，未复制框架代码或增加依赖。WordRogue保持单入口及现有四个autoload。
